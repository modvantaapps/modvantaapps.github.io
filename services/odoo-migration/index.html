What we do

Each Odoo version changes fields, views and frontend code, so custom modules have to be ported. We port modules between Odoo 17, 18 and 19, rewrite what the new framework no longer accepts, and test the result on a copy of your database before the switch.

Frequently asked questions

Which versions can you upgrade between?

We port modules between Odoo 17, 18 and 19.

Will our data be upgraded too?

The database upgrade itself depends on your edition: Enterprise uses Odoo's upgrade service, Community uses the community migration scripts. We port your custom modules and test the upgraded database.

How long does an upgrade take?

It depends on how many custom modules you have. We give you an estimate after the module audit.

Can we stay on our version and only fix problems?

Yes. We also maintain modules on the version you run today.

How does a migration from Odoo 18 to Odoo 19 work?

We list every custom and third-party module, port the ones you still need, then upgrade a copy of your database and let your team test it. Only when the copy works do we plan the switch on your live system, with a backup taken just before.

What changed in Odoo 19 that breaks custom modules?

Some fields are gone, such as the mobile field on contacts and the pricelist field on websites. SQL constraints are now declared with models.Constraint instead of _sql_constraints, and parts of the website JavaScript API changed. Modules that relied on these fail to install or show errors until they are ported.

Do you migrate third-party apps from the Odoo Apps Store?

If the author already publishes a version for your target release, we use it. If not, we port the module ourselves where its licence allows it, or suggest a replacement.
