What it does

Export orders, order items, invoices, credit memos, customers, products, stock and carts to Google BigQuery on a schedule, ready for Looker Studio and other BI tools. It uses free batch load jobs, keeps a change cursor per table, creates the dataset, tables and latest views for you, and lets you hash or leave out personal data.

This extension copies your store data to BigQuery so you can build sales reports and dashboards in Looker Studio or any other BI tool without running heavy queries against the shop database. A scheduled job reads orders, order items, invoices, credit memos, customers, products, stock and, if you want, carts, and sends only what changed since the last run using batch load jobs. It creates the dataset and tables for you, plus a _latest view per table that shows the current version of each record. In the admin, an Export Status page under System > BigQuery Export shows progress for each entity, with a Run Export Now button and a one-click backfill of history, and a run log lists every load job. Under Stores > Configuration you choose the entities, how often the export runs, the table prefix and dataset location, and whether e-mail addresses are hashed, personal data is left out or sent as is. The storefront does not change, and the full source code is included for your own additions. For example, a shop can chart revenue by day, track refunds by product or find its repeat customers.

Features

  • 8 tables with explicit schemas and a latest view per table
  • Incremental export by change date on a schedule from every 5 minutes to daily
  • Backfill of history with progress per table; a second click does not start it twice
  • Run Export Now and Run Now per table from the admin
  • Personal data modes: export as is, salted email hash only, or leave out entirely
  • Status page with rows exported, failures in a row, next attempt and last error
  • Run log with one line per load job, rows sent and loaded, and the BigQuery job ID
  • Service-account key stored encrypted and never shown again; Test Connection button
  • Separate permissions for viewing, running, backfilling and the log
  • Mock mode to try the whole flow without a Google account

Good to know

Requires a Google Cloud project with the BigQuery API and a service-account key with the BigQuery Data Editor and Job User roles, plus the store cron. Data arrives in batches, not in real time, and rows deleted in the store stay in BigQuery. Verified end to end in Mock mode; the real Google sign-in was checked only as far as Google's refusal of a test key, so confirm one load job on your own project first.

BigQuery Export: questions

Which Magento versions does BigQuery Export support?

Magento Open Source and Adobe Commerce 2.4 (developed and tested on 2.4.9), with PHP 8.1 to 8.5 and Luma-based themes. If your store runs Hyva or a headless front end, tell us first and we check it before you buy.

How much does BigQuery Export cost?

$30 as a one-time payment for one Magento installation. You get the full source code and a PDF user guide. There is no yearly fee.

How do I install BigQuery Export?

With Composer: composer require modvanta/module-big-query-export, then bin/magento setup:upgrade. We can also install and configure it on your store.
