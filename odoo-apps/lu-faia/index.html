Luxembourg FAIA SAF-T Audit File

Build the FAIA 2.01 file (Fichier Audit Informatise AED, the Luxembourg SAF-T) from your posted accounting, in the full, reduced A or reduced B schema, and validate it against the XSD the AED publishes before you hand it over.

What it does

checks before and after the file, plus the XSD

When the AED audits a Luxembourg business that keeps its books electronically, it can ask for the accounting data as a FAIA file: the Luxembourg version of the OECD Standard Audit File for Tax. This module writes that file from the posted entries of Odoo for the period you choose.

You pick the schema the AED describes for your situation: the full schema for integrated accounting and invoicing, reduced version A for accounting with invoicing (sales invoices only), or reduced version B for accounting alone. The three XSD files published by the AED ship with the module, unchanged, and every generated file is validated against the one you chose.

The module builds and stores the file. It sends nothing: you hand the file to the AED when they ask for it.

Who it is for

  • Luxembourg companies that keep their books in Odoo. When the AED asks for your accounting as a FAIA file, the Luxembourg SAF-T, this module writes it from the posted entries of the period you pick.
  • Fiduciaries and accountants answering an AED request. You choose the full schema, reduced version A or reduced version B, and every fichier audit informatise AED is validated against the official XSD before you hand it over.
  • Groups with several Luxembourg companies in one database. Each audit file belongs to one company, record rules keep the companies apart, and every file you generated stays on record with its period and schema.
  • Finance teams preparing before an audit. Run the checks on last year now. Missing registration numbers, a bad VAT number, draft entries or duplicate tax codes show up long before anyone asks for the file.

Setting it up

  1. Install the Luxembourg accounting localisation (l10n_lu), then this module. Odoo 19 Community or Enterprise both work.
  2. On the company, fill the Company ID with your matricule or RCS number and enter the Luxembourg VAT number. Make sure the company address has a city and a postal code.
  3. Give the contact person a first name, a last name and a telephone number, because the FAIA header needs all three.
  4. Optional: open Accounting > Configuration > Taxes and fill the FAIA Tax Code on each tax (9 characters at most), so the kinds of VAT stay apart. Without a code the tax's internal id is used.
  5. Go to Accounting > Reporting > Luxembourg FAIA > FAIA Audit Files and press New. Set the From and To dates, the Schema, the Tax Accounting Basis and the Contact Person.
  6. Press Run Checks and fix every line marked Fail. Then press Generate FAIA File, read the XSD Validation tab, and press Download to get the XML.

Luxembourg FAIA SAF-T Audit File: questions

Is this the same as SAF-T Luxembourg?

Yes. FAIA (Fichier Audit Informatise AED) is the Luxembourg version of the OECD Standard Audit File for Tax. The module writes FAIA 2.01, the version the AED publishes on pfi.public.lu, with the three XSD files shipped unchanged.

Do I need Odoo Enterprise for a Luxembourg SAF-T export?

No. This Luxembourg SAF-T module for Odoo runs on Community and on Enterprise, version 19. It depends only on Accounting, the Luxembourg localisation and the mail module.

Does it send the file to the AED?

No. Nothing is transmitted. The module builds, validates and stores the file, and you hand it to the AED yourself when they request it.

Which schema should I pick?

The AED FAQ says full for integrated accounting and invoicing, reduced A for accounting with an invoicing module, reduced B for accounting alone. If you invoice in Odoo, that is normally the full schema, which also carries purchase invoices and payments.

What is left out of the file?

Fixed assets and asset transactions, stock movements and physical stock, owners, taxonomies and analysis tables. Odoo Community has no asset module, and goods movements are not built in this version.

What if my books are not in euro or my year is not a calendar year?

The file can still be generated. Both cases raise a warning, not a failure: the AED expects one file per calendar year, and books in another currency need the conversion key handed over with the file.
