CyberSource Payment Gateway

CyberSource card payments inside the Odoo checkout

What it does

Visa Acceptance Solutions REST API with HTTP Signature authentication - or the Secure Acceptance Hosted Checkout for Secure Acceptance profiles. Decision Manager fraud screening decisions (review, reject) come back on the transaction

Who it is for

  • Online shops on a Visa Acceptance merchant account. A webshop that already has a CyberSource merchant ID can take card payments in the Odoo checkout. The card number and security code sit in CyberSource Microform fields, so Odoo only ever gets a token and the masked number.
  • Businesses whose bank issued a Secure Acceptance profile. Some banks hand out a profile ID, access key and secret key rather than a REST key. Set Checkout Type to the Hosted Checkout and customers are sent to the CyberSource payment page with a signed request.
  • Companies that send invoices and want them paid online. Customers open the invoice in the portal and pay it with the same card form. Once the payment is confirmed, Odoo marks the invoice as paid.
  • Sellers who authorize first and charge on shipment. With Capture Amount Manually ticked, the card is only authorized at checkout. You capture the full amount or void the authorization later from the Odoo transaction.

Setting it up

  1. In the CyberSource Business Center, open Payment Configuration > Key Management > Generate Key and create a REST - Shared Secret key. Copy the key ID and the shared secret.
  2. In Odoo, go to Invoicing > Configuration > Payment Providers and open CyberSource.
  3. Pick the Checkout Type: card fields on the Odoo page (Microform, REST API), or Secure Acceptance Hosted Checkout if you have a profile.
  4. Under REST API Key, fill in Merchant ID, Key ID and Shared Secret Key, then press Test Connection. For the Hosted Checkout, fill Profile ID, Access Key and Secret Key and paste the Merchant POST URL into your profile.
  5. Set the options: 3-D Secure (Payer Authentication), Send Order Lines and an optional Statement Descriptor. Tick Capture Amount Manually if you want authorize-only.
  6. Under Webhooks, press Register Webhook. The database needs to be reachable over HTTPS for this.
  7. Set the state to Test Mode to try the sandbox, then switch to Enabled and publish the provider on your website.

CyberSource Payment Gateway: questions

Do I need Odoo Enterprise?

No. The module depends only on the standard payment and account_payment modules, so it installs on Community as well as Enterprise.

Can I test before going live?

Yes. In Test Mode, REST calls go to apitest.cybersource.com and the Hosted Checkout posts to testsecureacceptance.cybersource.com. Switching to Enabled moves them to the production endpoints. Merchants boarded in India can pick the India production endpoint for the Hosted Checkout.

What if 3-D Secure isn't switched on for my CyberSource account?

The 3-D Secure option is on by default. If the Payer Authentication setup call fails because your account doesn't have it, the module carries on and pays without it, and the reason is written to the log. You can also switch the option off on the provider.

Can I do several partial captures on one authorization?

No. Captures are full-amount only, so one authorization is captured once for its whole amount. Refunds can be full or partial, from the normal Odoo refund button.

Do saved cards work with the Hosted Checkout?

No. Saved cards through the Token Management Service need the Microform checkout type. With the Hosted Checkout, capture, void and refunds from Odoo are only offered if you also enter a REST key; without one it takes sale payments only.

Where can I see what was sent to CyberSource?

Administrators get a CyberSource API Log menu under the payment configuration, plus an API Log button on the provider form. Every call and webhook is listed with its result, and tokens and card data are masked. A scheduled action also checks every 30 minutes on payments held for fraud review.
