Odoo Kafka integration

Kafka Connector

Send Odoo changes to Kafka topics, and turn Kafka messages into Odoo records.

View on Odoo Apps Store Ask a question
Apache Kafka and Odoo 19

What it does

Pick a model, the fields and the events. Odoo writes each change to an outbox in the same transaction and a scheduled job produces it to your topic through the Kafka REST Proxy. In the other direction, a consumer reads topics into a log or creates and updates records from signed messages.

The module talks to Kafka through the REST Proxy API, so nothing has to be installed on the Odoo server: no Kafka client library, no extra worker. Producing uses the v3 records endpoint, which works on a self-hosted REST Proxy, on Confluent Server and on Confluent Cloud. Consuming uses the v2 consumer instances of a self-hosted REST Proxy.

An event stream is one model, the fields you tick and a filter. On create, update or delete the change is written to the Kafka outbox inside the same database transaction. If the change is rolled back, the event is gone too. A job every two minutes sends the queue in order: key model/id, value JSON with the event, the record id, the company and your fields. Each record is read again with the rights of the user you choose, so record rules still apply.

Kafka answers HTTP 200 even when one record fails, so the module checks the error code of every delivery report. Failures wait 1, 2, 4, 8 minutes before the next try, and after the number of tries you set the event is marked Gave Up and a note is posted on the connection.

A consumer subscribes to topics, reads them on a schedule or when you press Read Now, and commits the offsets after Odoo has stored the messages. Keep them in the message log, or map message keys to fields of one model and let Odoo create or update records. That second mode only accepts messages signed with your secret, and it writes with the rights of the user you pick.
