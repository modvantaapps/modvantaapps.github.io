Odoo SaaS Kit

Odoo SaaS Kit - Multi Server SaaS with Docker, Custom Domains and Let's Encrypt

What it does

Publish SaaS plans on your website, let customers sign up for a free trial or pay online, and the module creates their own Odoo instance: a database on this server, or a Docker container on any of your servers (over SSH), on the Odoo version of the plan. It enforces user, app and storage limits, gives each customer a custom domain with a free Let's Encrypt certificate, meters usage for the invoice, backs instances up and restores them.

A visitor builds a plan on the signup page (extra users, optional apps, live price), picks an address and starts the trial or pays online. The queue picks the least loaded healthy server with room, creates the database or the container, installs the apps, sets the company and the customer login, applies the user limit and emails a link to set the password.

Remote hosts are reached with an SSH key; the host key fingerprint is checked on every connection. Every command is an argument list built from validated names, every operation is logged per server, and SSH keys and PostgreSQL credentials are visible to Settings administrators only.

Customers attach their own domain in the portal. When the DNS points to the server, the module requests a free certificate from Let's Encrypt (ACME, HTTP-01), writes the nginx site and renews the certificate 30 days before it expires.

Who it is for

  • Odoo partners selling hosted Odoo. A partner that sets up each client database by hand can publish plans on its website instead. A visitor picks a plan and an address, and a queued job creates the database, installs the plan's apps, sets up the company and login, and emails a link to set the password.
  • Vendors of industry modules who want trial signups. A software house with its own vertical modules can offer a free trial that installs those modules in a fresh instance. Trial reminders go out before the end, and expired trials are suspended and later dropped after the number of days you set.
  • Hosting providers running several servers. Instances can be plain databases on the Odoo server itself, or Docker containers on this machine or remote hosts reached over SSH. Each container runs the Odoo image of its plan, so a customer can stay on an older Odoo version.
  • Agencies that bill clients monthly for hosting. Plans carry a price per month or year, extra users and optional paid apps. A daily job creates the recurring invoices, adds measured usage when the plan bills for it, and can suspend instances whose invoices stay unpaid.

Features

You define plansapps installed, users included and maximum, price per month or year, price per extra user, optional paid apps, free trial days, and now the limits buyers ask for: maximum add-on apps, storage included (warn, suspend or invoice per extra GB), billing of measured users, custom domains allowed, fixed term, and the servers and Odoo version (Docker image) new instances of the plan use.

Setting it up

  1. Open the SaaS app and go to SaaS > Configuration > Settings. Set the Database Prefix, the Base Domain, the URL mode (subdomain per tenant or the ?db= parameter), and the trial, billing, backup and sign-up limits you want.
  2. For the single-server setup, configure wildcard DNS for the base domain and a dbfilter on the Odoo server so each subdomain opens its own database.
  3. To host in containers, add records under SaaS > Configuration > Servers with SSH access and capacity, press Check Server, and list the Docker images you offer under SaaS > Configuration > Odoo Versions.
  4. Create plans under SaaS > Plans: choose the modules installed, Users Included and Maximum Users, price and billing period, trial days, Optional Paid Apps, storage included and what happens Over the Storage Limit.
  5. Publish the plans. Visitors see them at /saas/plans, build their plan on the signup page with a live price, and start a trial or go to the order to pay.
  6. Follow everything under SaaS > Instances, where you can Suspend, Reactivate, Change Plan, Backup Now, Restore or Terminate. Custom domains, backups and usage readings each have their own menu.

Odoo SaaS Kit: questions

Which Odoo apps does it need?

Website, Sales, Invoicing, Portal and Discuss, all available in Community. Online payment of the signup order uses whatever payment provider you've set up in Odoo.

Do I have to store the database master password?

No. Databases are created without the database manager master password, so it isn't kept in Odoo at all.

What do remote Docker hosts need?

Docker, an env file with the PostgreSQL connection, and SSH key login. The host key fingerprint is checked on every connection and a saved key is never replaced silently. Custom domains also need nginx and port 80 open on that host.

How do custom domains and certificates work?

A customer adds their domain in the portal. Once its DNS points to the server, the module requests a free Let's Encrypt certificate over HTTP-01, writes the nginx site, tests it with nginx -t, reloads nginx and renews the certificate 30 days before it expires.

What happens to a customer's data when they leave?

Terminating an instance takes a final backup first. Backups use Odoo's zip format and can be restored as a new instance with its own database UUID, or in place after a safety backup is taken.

How are user limits enforced?

A job reads user counts and database sizes every six hours and the instance list flags tenants over their user or storage limit. If you switch on Enforce User Limit in Databases, the limit is also applied inside the customer's database.
