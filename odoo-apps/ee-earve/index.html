Estonia e-Invoice (e-arve XML 1.2)

Estonia e-Invoice for Odoo 19: e-arve XML 1.2 files checked against the official schema, batch export, viitenumber and bill import

View on Odoo Apps Store Ask a question

What it does

Turns your posted customer invoices and credit notes into the national Estonian e-invoice file (standard version 1.2), ready for your e-invoice operator or internet bank. It also reads the same files back in as vendor bills.

e-arve XML 1.2 generator: seller, buyer, invoice data, sums, one VAT block per rate, item rows with discounts, payment block and file footer, in the order the schema asks.

Who it is for

  • Estonian companies whose customers ask for e-arve files. Some Estonian buyers want invoices in the national e-arve XML format rather than as a PDF. The module builds that file from each posted customer invoice or credit note and checks it against the official XSD before saving it.
  • Businesses that upload invoices to an operator or internet bank. Instead of exporting invoices one by one, you select them in the list and export a ZIP with one file each, or a single file holding them all with control totals in the footer.
  • Accountants receiving e-arve files from suppliers. Dropping a supplier's e-arve XML on the Bills screen creates the vendor bill with lines, taxes and reference filled in. Files with several invoices and files carrying an embedded PDF are read too.
  • Companies that use Estonian reference numbers. The journal can generate a viitenumber with the 7-3-1 check digit, based on the invoice or on the customer, so payments are easier to match.

Features

Checked before it is savedevery file is validated against the official XSD published by ITL. A missing bank account or registry code is explained in plain words on the invoice.
Batch exportselect invoices, then Print -> E-Arve XML. Get a ZIP with one file per invoice, or one file holding all of them with the control totals in the footer.
Estonian reference number (viitenumber)a journal reference model with the 7-3-1 check digit, per invoice or per customer.
Registry code checka warning on the contact when the check digit of a registrikood or personal code does not match.
Routing per customerchannel, channel address and client number, plus test flag, sender, receiver and contract in the file header.
Email and automationattach the XML to the customer email, generate it on posting, embed the PDF inside the XML if your operator wants it.
Import to vendor billsdrop an e-arve XML on the Bills screen. Seller, lines, taxes, reference, credit invoices, multi-invoice files and the embedded PDF are read.

Setting it up

  1. Make sure the Estonian accounting localization is installed, then fill in your company's registry code and the bank account used on invoices.
  2. Go to Accounting > Configuration > Settings and find the Estonian e-invoice (e-arve) section. Choose whether to generate e-arve on posting, attach it to emails, embed the invoice PDF, or mark files as test.
  3. If your operator or bank asks for them, fill in the Operator details: File sender ID, File receiver ID and Operator contract ID.
  4. On the sales journal, open Advanced Settings and set Communication Standard to Estonian reference number (viitenumber).
  5. On each customer that needs routing, open the Invoicing tab and fill in e-arve channel, e-arve channel address and e-arve client number.
  6. Post an invoice and press Generate e-arve, then Download e-arve XML. For a batch, select invoices in the list and choose Print > E-Arve XML.

Estonia e-Invoice (e-arve XML 1.2): questions

Does it need Odoo Enterprise?

No. It depends on the Estonian accounting localization (l10n_ee), which is available in Community. It works the same on Enterprise.

Does it send the files to my e-invoice operator?

No. It creates the XML files, and you upload them to your operator or bank or send them to the customer by email. There's no operator API connection in the module.

How does it relate to Peppol?

Odoo has its own Peppol BIS 3 support, and this module doesn't change it. It adds the national e-arve 1.2 format, which is a separate file standard. Check with your accountant or operator which format each customer needs.

What happens if an invoice is missing data?

The invoice is marked as needing fixing and the problems are listed in plain words, such as a missing bank account or registry code. When generation on posting is on, a problem never blocks the posting itself.

How are credit notes written?

They're written as type CRE with negative sums and an amount to pay of zero. The format description has no credit example, so ask your operator to confirm they read it the same way. Your accountant should also confirm how credit notes are treated for VAT.

Can I invoice a private person with no registry code?

Yes. The format allows an empty registry number for a private customer. A company customer needs a registry code or a VAT number, and the contact shows a warning when a registry or personal code has a wrong check digit.
