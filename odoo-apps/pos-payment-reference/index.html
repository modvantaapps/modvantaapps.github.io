POS Payment Reference

Record the card slip, cheque or transaction number on every POS payment

View on Odoo Apps Store Ask about customisation

What it does

Each payment method can ask the cashier for a reference: optional or required, with its own name, a minimum length and a check against references already used. The reference is printed on the receipt, searchable in the backend and listed in the session report.

When a customer pays by card on a separate terminal, by cheque or by bank transfer, the till only records the amount. At the end of the day nobody can match a POS payment to the terminal slip or the cheque that was paid in.

This module adds a reference to every POS payment line. On each payment method you choose whether a reference is not used, optional or required, what it is called (for example Card slip number or Cheque number), its minimum length, and whether a reference that was already used must be refused.

On the payment screen the cashier is asked for the reference as soon as a required method is chosen, and the order cannot be validated without it. The server checks every paid order again, so a duplicate reference is refused even when the till let it through. The reference is printed on the receipt, stored on the payment, searchable in Point of Sale -> Orders -> Payments and listed in the session report.

Who it is for

  • Shops with a standalone card terminal. When the card machine isn't connected to Odoo, the till only knows the amount. Making the slip number required on the Card method means every card payment can be matched to its terminal slip when the session is closed.
  • Businesses that take UPI or bank transfers. Counter staff type the transaction id from the customer's phone or the transfer confirmation. With duplicate checking on, the same screenshot shown twice is refused, and the error names the order it was first used on.
  • Stores that still accept cheques. Set the Cheque method to Optional or Required and call the reference Cheque number. It gets printed on the receipt and listed in the session report, which saves a separate paper register.
  • Bookkeepers reconciling POS payments. References are searchable under Point of Sale > Orders > Payments and shown per order. On invoiced orders they're also added to the label of the payment journal entry Odoo creates, so a bank line is easier to trace.

Setting it up

  1. Install the module. It depends only on Point of Sale.
  2. Go to Point of Sale > Configuration > Payment Methods and open a method, for example Card.
  3. Set Payment Reference to No reference, Optional or Required.
  4. Fill in Reference Name (for example Card slip number). If you leave it empty, the cashier and the receipt see Ref.
  5. Set Minimum Length if you want to stop one-character entries, and tick Refuse a Reference Already Used to block duplicates on that method.
  6. Reload the till. When the cashier picks a Required method, a popup asks for the reference straight away, and the reference button on the payment line turns red until it's filled.
  7. To review, use Point of Sale > Orders > Payments with the With Reference and Missing Required Reference filters, or print the session's sales details report, which now has a Payment References section.

POS Payment Reference: questions

Can a cashier get around a required reference?

Not easily. The till won't validate the order without it, and the server checks every paid order again when it arrives. A missing, too short or duplicated reference makes the server refuse the order with a message listing the problems.

What about payment terminals that are integrated with Odoo?

If a method uses an integrated payment terminal, the popup isn't shown when the method is picked. A transaction id or reference number sent back by the terminal counts as the reference, so a Required rule is satisfied by it.

How does the duplicate check work?

With Refuse a Reference Already Used ticked, the server looks for the same reference on any other payment of that same method, ignoring upper or lower case. The same number used on a different payment method isn't treated as a duplicate.

Does it apply to payments added from the backend?

Yes. The standard Payment wizard on a POS order already has a Payment Reference box. The module stores that value as the reference and applies the same Required, minimum length and duplicate rules.

Will the reference show up in my accounting?

For invoiced orders, each payment gets its own journal entry and the reference is added to its label. At session closing, Odoo normally sums payments into one line per method, so a single reference can't be shown there. Methods that create one line per customer payment carry the reference on that line.

Can I change the rules while a session is open?

Yes. The server applies the new rules at once. The till picks them up after it's reloaded.
